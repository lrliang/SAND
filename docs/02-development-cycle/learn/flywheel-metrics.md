# 飞轮加速度量

3 核心指标：资产复用率（30%-70% 健康）、意图首通率（>60% 合格，成熟 80%+）、循环周期压缩率（<1.0 表示加速）。三者同时改善才是真正的飞轮加速。

---

## 概述

飞轮效应（Flywheel Effect）是 SAND Learn 阶段的核心价值主张。它的含义不是"做复盘"，而是**每一轮 SDC 循环的产出使下一轮循环更快、更好**——形成越转越快的正向循环。

### 飞轮的具体运转机制

```
Learn 产出 AI 资产
    │
    ├──→ Intent 提升首通率（意图模式提供编写模板和约束参考）
    │
    ├──→ Orchestrate 提高编排效率（上下文资产 + 编排配方 + 失败案例减少试错）
    │
    └──→ Validate 增强覆盖面（验证规则补充领域特定检查项）
              │
              └──→ 更高质量的交付 → 更少的偏差 → 更快的循环
                        │
                        └──→ 更多的 Learn 产出 → 飞轮加速
```

飞轮是否真正在加速，不能凭感觉判断。SAND 定义了 3 个可量化的核心指标，用于度量飞轮的健康状态。

---

## 指标 1：资产复用率

### 定义

> **资产复用率** = 引用了已有 AI 资产的意图数 ÷ 总意图数

衡量团队在启动新的 SDC 循环时，是否在利用前序循环积累的知识资产。

### 计算方法

```
asset_reuse_rate = count(intents with asset_references > 0) / count(all_intents)
```

其中 `asset_references` 包括：
- 意图声明的 `context_references` 中引用了 AI 资产
- 编排方案中使用了编排配方资产
- 验证过程中应用了验证规则资产

### 数据源

| 数据 | 位置 | 采集方式 |
|------|------|---------|
| 意图声明引用记录 | `.sand/intents/INT-*.yaml` | 扫描 `context_references` 字段中 `AST-*` 格式的引用 |
| 编排方案引用 | `.sand/executions/orchestration-plan.yaml` | 扫描 `recipe_reference` 字段 |
| 验证规则引用 | 验证 step 执行日志 | 审计事件中的辅助数据 |

### 基准值与解读

| 区间 | 状态 | 解读 |
|------|------|------|
| **< 30%** | 资产库不够丰富 | 资产库中的资产太少或不够有用——需要增加资产化投入 |
| **30%-70%** | 健康 | 团队在有效利用前序知识，同时也在探索新领域 |
| **> 70%** | 过度复用风险 | 可能过度依赖已有模式而缺少创新——需检查是否在机械套用而非适配性使用 |

### MVP 采集方式

Phase 2 基础版：在复盘结构化日志中手动记录"本轮是否引用了已有资产"（二值）。
Phase 3 完整版：自动扫描 `.sand/intents/` 和 `.sand/executions/` 中的资产引用。
Phase 4+：向量数据库自动相似度检索。

## 指标 2：意图首通率

### 定义

> **意图首通率**（Intent First-Pass Rate）= Draft → Validated 无回退的意图数 ÷ 总意图数

衡量意图声明的一次性质量——意图从创建到通过验证，中间无 CLEAR 检查失败回退、无验证打回重建。

### 计算方法

```
intent_first_pass_rate = count(intents: Draft → Validated without rejection) / count(all_completed_intents)
```

"无回退"的判定：
- CLEAR 检查一次通过（无 ⚠️ 或 ✗ 需修改后重新检查）
- Validate 决策为 `pass` 或 `conditional_pass`（非 `reject_to_build` 或 `redirect_to_intent`）

### 数据源

| 数据 | 位置 | 采集方式 |
|------|------|---------|
| 意图状态转换记录 | `.sand/intents/INT-*.yaml` frontmatter `meta.status` | 追踪状态机转换历史 |
| CLEAR 检查结果 | 执行日志 / 审计事件 | `sdc_phase=intent` 的审计事件 |
| 验证决策 | `.sand/executions/EXE-*/validation-report.yaml` | `decision` 字段 |

### 基准值与解读

| 区间 | 状态 | 对标 |
|------|------|------|
| **< 40%** | 低——意图编写质量需系统性改善 | 新用户初期常见 |
| **40%-60%** | 中——正在建立有效的意图编写实践 | 新用户 3 天后目标 |
| **≥ 60%** | 合格——达到 PRD 成功标准 | PRD Measurable Outcomes 目标 |
| **80%+** | 成熟——意图模式库有效运作 | 成熟团队标杆 |

### 与 PRD 成功标准对齐

PRD 定义的 P0 成功标准（陈雨旅程）："新用户（3 年+ 工程经验，未使用过 SAND）连续 3 天使用"，意图首通率 ≥60%。此基准值与 PRD Measurable Outcomes 表中的"意图首通率 ≥60%（新用户 3 天后）"完全一致。

## 指标 3：循环周期压缩率

### 定义

> **循环周期压缩率** = 本轮 SDC 周期时长 ÷ 前轮 SDC 周期时长

衡量 SDC 循环是否在加速——相似复杂度的任务，完成一轮循环所需的时间是否在减少。

### 计算方法

```
cycle_compression_rate = duration(current_cycle) / duration(previous_cycle)
```

其中 `duration` = 从 Intent 阶段启动到 Validate 阶段完成的端到端时间。

**重要约束：** 此指标仅在**相似复杂度的循环**之间有意义。复杂度差异大的循环之间的时长对比没有参考价值。MVP 阶段复杂度归一化由人工判断。

### 数据源

| 数据 | 位置 | 采集方式 |
|------|------|---------|
| 循环起止时间戳 | `.sand/executions/EXE-*/execution.yaml` | `started_at` 和 `completed_at` 字段 |
| 审计事件时间线 | `.sand/audits/audit.jsonl` | 同一 `execution_id` 的首尾事件时间差 |

### 基准值与解读

| 值 | 状态 | 解读 |
|----|------|------|
| **< 0.8** | 显著加速 | 飞轮效应明显——前序资产大幅减少工作量 |
| **0.8-1.0** | 轻微加速 | 飞轮正在运转但效果尚不显著 |
| **= 1.0** | 持平 | 飞轮未加速——需检查资产是否被有效利用 |
| **> 1.0** | 减速 | 可能原因：任务复杂度上升、团队变动、资产过时 |

### 与 sand-measure-light 的关系

循环周期压缩率的数据采集（执行时间戳）可由 `sand-measure-light` Skill（Story 7-1）自动完成。两者的分工：

- **sand-run-retrospective**：在复盘时使用压缩率作为飞轮健康度判断的输入
- **sand-measure-light**：负责底层数据的自动采集和持久化到 `.sand/metrics/`

## 飞轮健康度综合判断

### 三指标联动分析

单个指标的改善不代表飞轮在加速——需要三指标联动分析：

| 场景 | 复用率 | 首通率 | 压缩率 | 诊断 |
|------|--------|--------|--------|------|
| **飞轮加速** | ↑ | ↑ | < 1.0 | 理想状态——资产有效利用，质量提升，速度加快 |
| **空转** | ↑ | → | ≈ 1.0 | 资产被引用但未带来质量或速度改善——检查资产质量 |
| **虚假加速** | → | → | < 1.0 | 速度加快但未利用资产——可能是走捷径而非系统性改善 |
| **资产过时** | ↓ | ↓ | > 1.0 | 飞轮在减速——资产库需要大规模刷新 |
| **单维突破** | ↑ | ↑ | > 1.0 | 资产和质量改善但任务复杂度上升抵消了速度收益——正常 |

### 飞轮停滞诊断路径

当飞轮指标显示停滞或减速时，按以下路径诊断：

1. **复用率 < 30%？** → 资产库内容不足或不可发现——增加资产化投入，改善元数据和标签
2. **复用率 > 30% 但首通率无改善？** → 资产质量问题——触发资产审查，检查过时资产
3. **首通率改善但压缩率 ≥ 1.0？** → 非意图阶段存在瓶颈——检查 Build 和 Validate 阶段耗时
4. **三指标均下降？** → 系统性退化——建议运行 `sand-assess-maturity` 重新评估"学习与资产化"维度

### learning_signal 完整度追踪

飞轮数据质量取决于上游数据的完整度。偏差事件（参见 [偏差追踪](../validate/deviation-tracking.md)）中 `learning_signal` 字段的填充率直接影响 Learn 阶段的资产化质量：

| 填充率 | 状态 | 行动 |
|--------|------|------|
| **≥ 80%** | 健康 | 飞轮数据源充足 |
| **50%-80%** | 需关注 | 部分偏差未提取学习信号——在复盘议题 4 中补充 |
| **< 50%** | 飞轮静默退化 | 大量偏差未产出学习信号——飞轮缺少燃料 |

## MVP 度量实现策略

| Phase | 实现级别 | 说明 |
|-------|---------|------|
| **Phase 2** | 手动记录 | 复盘结构化日志中包含三指标快照（人工填写或 AI 辅助计算） |
| **Phase 3** | 自动计算 | `sand-run-retrospective` 完整版自动从 `.sand/` 数据计算三指标 + 趋势分析 |
| **Phase 4** | 可视化 | `sand-measure-light` + 可视化仪表盘，飞轮健康度实时追踪 + 预警 |

Phase 2 的"手动记录"意味着飞轮指标快照嵌入复盘日志的末尾（参见 [AI 复盘标准议程 §复盘输出格式](./ai-retrospective.md#复盘输出格式)），由 AI 引导计算、人类确认。

**对 SAND 的实践意义：** 飞轮度量将"持续改进"从组织文化层面的口号转化为可量化、可追踪的工程指标。三指标联动分析确保团队不会陷入"单维度优化"的陷阱——只有资产利用、意图质量和循环速度同步改善，才是真正的飞轮加速。这也是 SAND "学习与资产化"维度从 L3（系统化）到 L4（量化管理）的关键跨越标志。
