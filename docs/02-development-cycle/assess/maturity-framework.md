# 7 维度成熟度评估框架

7 个评估维度（AI 工具采纳度、意图驱动成熟度、编排能力、人类审查体系、学习与资产化、治理与合规、组织文化），每个维度有 L1-L5 的具体描述和证据类型。

---

## 框架概述

SAND 成熟度评估框架通过 **7 个维度 × 5 个等级** 构建组织的 AI 原生成熟度画像。每个维度映射到 SDC（SAND Development Cycle）的一个或多个阶段，确保评估结果直接指向可执行的改进路径。

### 等级定义（通用）

| 等级 | 名称 | 核心特征 |
|------|------|---------|
| **L1** | 初始/无意识 | AI 使用碎片化、无标准化流程、个人行为为主 |
| **L2** | 可重复/有意识 | 初步标准化、关键流程有覆盖但不完整、团队层面有意识 |
| **L3** | 已定义/系统化 | 全流程标准化、有度量和反馈机制、组织层面推行 |
| **L4** | 量化管理/优化 | 数据驱动决策、持续优化循环、跨团队一致 |
| **L5** | 持续演进/自适应 | 自适应学习、框架级创新、组织文化内化 |

每级是前一级的超集——达到 L3 意味着 L1 和 L2 的所有行为已稳定内化。

### 维度与 SDC 阶段映射

| # | 维度 | 主要映射 SDC 阶段 | 理论基础 |
|---|------|-----------------|---------|
| D1 | AI 工具采纳度 | 全阶段（基础设施层） | AI 原生谱系（行业共识 + Hassan SE 3.0） |
| D2 | 意图驱动成熟度 | Intent | Hassan SE 3.0 |
| D3 | 编排能力 | Orchestrate | 多 Agent 编排理论 |
| D4 | 人类审查体系 | Validate + Build | Fowler 约束工程 |
| D5 | 学习与资产化 | Learn | Fowler 认知债务 |
| D6 | 治理与合规 | Governance | ISO 42001 + NIST AI RMF |
| D7 | 组织文化 | 全阶段（组织层） | 渐进采纳理论 |

## D1：AI 工具采纳度

**定义：** 组织在开发全生命周期中引入和标准化 AI 工具的广度和深度。

**理论映射：** AI 原生三级谱系（AI 赋能 → AI 优先 → AI 原生），参见 [ai-native-definition.md](../../01-foundations/ai-native-definition.md)

| 等级 | 行为指标 | 证据类型 | 采集方式 |
|------|---------|---------|---------|
| **L1** | - 个别工程师自发使用 AI 编码助手 | 工具安装数、个人许可证 | 手动：问卷 |
|  | - 无组织层面的 AI 工具策略 | 策略文档缺失 | 手动：文档检查 |
| **L2** | - 团队层面统一了 AI 编码工具（如 Cursor/Claude Code） | 许可证分配记录 | 自动：许可证管理系统 |
|  | - 有基础的使用指南（如禁止在 AI 对话中输入敏感数据） | 指南文档 | 手动：文档检查 |
| **L3** | - AI 工具覆盖开发全生命周期（编码、测试、审查、文档） | 工具矩阵文档 | 手动：工具审计 |
|  | - 工具选型有标准化流程（评估 → 试用 → 推广） | 选型记录 | 手动：流程审计 |
| **L4** | - AI 工具使用有量化度量（AI 参与度、接受率、拒绝率） | 度量仪表盘 | 自动：IDE 遥测 |
|  | - 基于度量数据持续优化工具配置和提示词策略 | 优化记录 | 混合 |
| **L5** | - 组织主动评估和引入新兴 AI 工具（如从 Copilot → Cursor → 自研） | 工具演进路线图 | 手动：策略审查 |
|  | - AI 工具选型影响组织架构决策（如选择支持特定 Agent 协议的平台） | 架构决策记录 | 手动：ADR 审查 |

## D2：意图驱动成熟度

**定义：** 组织将开发需求从自由格式的自然语言转化为结构化意图声明的程度和质量。

**理论映射：** Hassan SE 3.0 意图驱动范式，参见 [cognitive-collaboration.md](../../01-foundations/cognitive-collaboration.md)

| 等级 | 行为指标 | 证据类型 | 采集方式 |
|------|---------|---------|---------|
| **L1** | - 开发者直接在 AI 工具中输入自由格式提示词 | 对话历史（抽样） | 手动：抽样审查 |
|  | - 无标准化的需求-到-实现传递格式 | 需求文档格式 | 手动：文档检查 |
| **L2** | - 团队有"好的提示词"模板或最佳实践清单 | 模板文档 | 手动：文档检查 |
|  | - 关键功能开发前有简短的需求描述（但非结构化意图声明） | 需求描述文档 | 手动：抽样审查 |
| **L3** | - 使用结构化意图声明（含 purpose、desired_outcome、acceptance_criteria 等字段） | 意图声明文件 | 自动：文件存在性检查 |
|  | - 意图声明有质量检查流程（如 CLEAR 检查） | 检查记录 | 自动：CLEAR 通过率 |
| **L4** | - 意图首通率（Intent First-Pass Rate）≥60% | 度量数据 | 自动：状态机追踪 |
|  | - 意图声明自动生成执行契约（must_pass/should_pass/must_not_violate） | 契约文件 | 自动：文件存在性 |
| **L5** | - AI 主动识别意图声明中未覆盖的边界条件并请求澄清 | 边界条件澄清记录 | 自动：对话日志分析 |
|  | - 意图模式库不断积累并被复用（从历史意图中学习） | 资产库记录 | 自动：复用率追踪 |

## D3：编排能力

**定义：** 组织设计和执行多 Agent 协作方案的结构化程度。

**理论映射：** 多 Agent 系统编排理论（六大编排模式），参见 orchestrate/ 阶段文档

| 等级 | 行为指标 | 证据类型 | 采集方式 |
|------|---------|---------|---------|
| **L1** | - 开发者在单个 AI 会话中完成所有工作（无编排概念） | 工作方式观察 | 手动：访谈 |
|  | - 无 Agent 角色区分 | 使用模式 | 手动：访谈 |
| **L2** | - 团队意识到不同任务适合不同的 AI 交互模式 | 使用指南 | 手动：文档检查 |
|  | - 偶尔使用多轮对话来分解复杂任务 | 对话历史 | 手动：抽样审查 |
| **L3** | - 使用标准化编排拓扑（Solo/Pipeline/Swarm/Hierarchy） | 编排方案文件 | 自动：文件检查 |
|  | - 有 Agent 角色定义（如问题域负责人、FDE+、变革催化师） | 角色配置 | 手动：配置审查 |
| **L4** | - 编排方案基于意图特征自动推荐拓扑类型 | 推荐记录 | 自动：编排日志 |
|  | - 外部 Skill 通过插件机制接入编排层 | 插件注册记录 | 自动：registry 检查 |
| **L5** | - 编排方案根据执行反馈动态调整（如自动降级拓扑） | 调整记录 | 自动：执行日志 |
|  | - 跨项目的编排模式被抽象为可复用的"编排配方" | 资产库记录 | 自动：复用率 |

## D4：人类审查体系

**定义：** 组织在 AI 参与的开发流程中建立的结构化人类审查和质量控制机制的完善程度。

**理论映射：** Fowler 约束工程（计算控制 + 推断控制），参见 [non-deterministic-paradigm.md](../../01-foundations/non-deterministic-paradigm.md)

| 等级 | 行为指标 | 证据类型 | 采集方式 |
|------|---------|---------|---------|
| **L1** | - AI 生成的代码直接合并，无专门审查流程 | PR 审查记录 | 自动：Git PR 数据 |
|  | - 代码审查不区分人工编写和 AI 生成的代码 | 审查策略文档 | 手动：文档检查 |
| **L2** | - AI 生成代码有标识（如 commit message 标注） | Git 提交历史 | 自动：commit 分析 |
|  | - 关键模块的 AI 生成代码需额外人工审查 | 审查策略 | 手动：流程检查 |
| **L3** | - 三层审查策略：第一层自动化 lint/test → 第二层 AI 辅助审查 → 第三层人工深度审查 | 审查配置 | 混合 |
|  | - HIP 级别已配置（HIP-1/2/3 根据任务风险区分） | HIP 配置 | 手动：配置检查 |
| **L4** | - 三通道并行验证（契约/安全/架构）全面运行 | 验证报告 | 自动：验证日志 |
|  | - 审查效率有度量（PR 审查中位时间、变更失败率）且持续优化 | 度量仪表盘 | 自动：Git/CI 数据 |
| **L5** | - 约束工程体系完善（计算控制 + 推断控制双层） | 约束配置 | 混合 |
|  | - 审查策略根据历史数据自动调整（如高风险模块自动升级 HIP 级别） | 调整记录 | 自动 |

## D5：学习与资产化

**定义：** 组织从 AI 协作经验中提取、结构化和复用知识资产的系统性程度。

**理论映射：** Fowler 认知债务警告——AI 大量生成代码时团队是否还在学习？

| 等级 | 行为指标 | 证据类型 | 采集方式 |
|------|---------|---------|---------|
| **L1** | - 无复盘机制，AI 协作经验留在个人记忆中 | 复盘记录缺失 | 手动：流程检查 |
|  | - 团队重复遇到相同的 AI 协作问题 | 问题追踪记录 | 手动：访谈 |
| **L2** | - 偶尔做 AI 相关的回顾/复盘 | 复盘记录 | 手动：记录检查 |
|  | - 有团队内部的"AI 使用心得"分享 | 分享记录 | 手动：记录检查 |
| **L3** | - 5 议题标准化 AI 复盘流程定期运行 | 复盘结构化输出 | 自动：文件检查 |
|  | - AI 资产分类体系建立（上下文资产、意图模式、编排配方、验证规则、失败案例） | 资产库 | 自动：资产库检查 |
| **L4** | - 资产复用率可追踪（从历史资产中获益的 SDC 循环占比） | 复用率度量 | 自动：资产引用追踪 |
|  | - 飞轮加速指标有改善趋势（资产复用率↑、意图首通率↑、循环周期↓） | 趋势图 | 自动：度量仪表盘 |
| **L5** | - 资产库成为组织记忆的核心——新成员通过资产库而非口耳相传上手 | 入职流程 | 手动：流程审查 |
|  | - 跨团队资产共享和交叉授粉 | 共享记录 | 混合 |

## D6：治理与合规

**定义：** 组织对 AI 参与的开发决策进行结构化审计和合规管理的完善程度。

**理论映射：** ISO/IEC 42001 AI 管理系统 + NIST AI RMF，参见 [agentic-consensus.md](../../01-foundations/agentic-consensus.md)

| 等级 | 行为指标 | 证据类型 | 采集方式 |
|------|---------|---------|---------|
| **L1** | - 无 AI 决策审计机制 | 审计记录缺失 | 手动：流程检查 |
|  | - 无法回答"AI 为什么做了这个决策" | 决策追溯能力 | 手动：模拟审计 |
| **L2** | - AI 使用有基础记录（如哪些代码是 AI 生成的） | Git 标注记录 | 自动：commit 分析 |
|  | - 有 AI 使用政策文档（允许/禁止的使用场景） | 政策文档 | 手动：文档检查 |
| **L3** | - 审计事件自动记录（intentId、skillVersion、actor、timestamp） | .sand/audits/ | 自动：审计日志检查 |
|  | - 每个人工确认点有时间戳和确认记录 | 确认记录 | 自动：审计日志 |
| **L4** | - 意图→Skill→决策的完整证据链可追溯 | 审计追踪报告 | 自动：证据链分析 |
|  | - 审计报告可导出为标准格式（JSON/CSV）供外部审计师审查 | 导出报告 | 自动：导出功能 |
| **L5** | - 与行业合规标准的映射已建立（ISO 42001 / EU AI Act / SOC2） | 合规映射文档 | 手动：合规审查 |
|  | - 持续合规基础设施——每次 SDC 循环自动积累审计证据 | 自动化程度 | 自动 |

## D7：组织文化

**定义：** AI 协作理念在组织各层级的内化程度和变革推进的有效性。

**理论映射：** 渐进采纳理论——最小切口 → 单 Skill → 单团队 → 可见效果 → 自然扩散

| 等级 | 行为指标 | 证据类型 | 采集方式 |
|------|---------|---------|---------|
| **L1** | - AI 使用是个人选择，组织无态度 | 组织沟通记录 | 手动：访谈 |
|  | - 部分团队成员对"又一个框架/工具"有抵触情绪 | 团队反馈 | 手动：匿名调查 |
| **L2** | - 组织明确鼓励 AI 使用，提供工具和预算 | 预算记录、公告 | 手动：记录检查 |
|  | - 有 AI 相关的培训或分享活动 | 培训记录 | 手动：记录检查 |
| **L3** | - 有明确的变革催化师角色或工程效能团队推动 AI 采纳 | 角色分配 | 手动：组织图检查 |
|  | - 采用"最小切口"策略：从单个痛点 → 单个 Skill → 单个团队 → 验证效果 | 实验记录 | 手动：记录检查 |
| **L4** | - 多团队自然扩散——后续团队主动请求采纳而非被推动 | 采纳记录 | 手动：记录检查 |
|  | - 数据驱动的认知失调报告推动变革（正向+负向指标对比） | 度量报告 | 混合 |
| **L5** | - AI 协作理念内化为组织文化——不需要专门推动 | 文化评估 | 手动：文化调查 |
|  | - 组织为 AI 协作设计了新的角色和职责（如 FDE+、Mission Pod） | 组织架构 | 手动：组织图检查 |

## 评估方法论

### 评估模式

`sand-assess-maturity` 支持两种评估模式：

1. **首次诊断模式**：全面组织评估，覆盖全部 7 维度 × L1-L5，产出完整雷达图。适用于组织首次接触 SAND 的场景。
2. **循环校准模式**：基于上轮 Learn 阶段的输出，快速检查特定维度的变化。适用于持续改进循环。

### 评级规则

每个维度的等级判定规则：

- **达到某等级**要求该等级的**所有**行为指标都已满足
- **部分满足**不提升等级——仅在当前等级行为指标全部满足时才升级
- 评估以**证据为导向**——自我感知不计入评级，必须有可验证的证据

### 雷达图生成

7 维度的评估结果以雷达图（也称蛛网图）形式可视化：

- 每个维度一条轴线，L1-L5 对应 1-5 的径向刻度
- 红色区域：L1-L2（需要立即改进）
- 黄色区域：L3（已标准化，可持续优化）
- 绿色区域：L4-L5（优秀，维持和扩展）

雷达图的**形状**揭示组织的成熟度特征（参见 [gap-analysis.md](./gap-analysis.md)）。

## YAML 化提取指南

本框架的结构设计直接支持向 `data/dimension-rubrics.yaml` 的操作化提取：

```yaml
# 示例：dimension-rubrics.yaml 的预期结构
dimensions:
  - id: D1
    name: "AI 工具采纳度"
    sdc_phase: "全阶段"
    theory_basis: "AI 原生谱系（行业共识 + Hassan SE 3.0）"
    levels:
      L1:
        name: "初始/无意识"
        indicators:
          - "个别工程师自发使用 AI 编码助手"
          - "无组织层面的 AI 工具策略"
        evidence:
          - type: "工具安装数"
            collection: "手动"
          - type: "策略文档缺失"
            collection: "手动"
      L2:
        # ...
```
