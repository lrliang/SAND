# 差距分析与转型路径

雷达图诊断 + 转型路径生成。三种组织形状（均衡型/偏科型/尖刺型）及对应的转型策略模板。

---

## 概述

成熟度评估（[maturity-framework.md](./maturity-framework.md)）产出 7 维度的等级数据。差距分析的职责是**将这组数据转化为可执行的改进路径**——告诉用户"先做什么、怎么做、预期多久见效"。

这是 SAND "诊断即处方"核心假设的实现层：评估不止于告诉你"哪里红了"，而是直接生成行动方案。

---

## 雷达图诊断方法论

### 雷达图生成逻辑

`sand-assess-maturity` Skill 在完成 7 维度评估后，将结果组织为雷达图（蛛网图）数据：

```yaml
# 雷达图数据结构
radar_chart:
  team_id: "team-alpha"
  timestamp: "2026-05-13T10:30:00Z"
  dimensions:
    - id: D1
      name: "AI 工具采纳度"
      level: 4
    - id: D2
      name: "意图驱动成熟度"
      level: 1
    - id: D3
      name: "编排能力"
      level: 1
    - id: D4
      name: "人类审查体系"
      level: 1
    - id: D5
      name: "学习与资产化"
      level: 1
    - id: D6
      name: "治理与合规"
      level: 2
    - id: D7
      name: "组织文化"
      level: 3
```

### 颜色编码

| 颜色 | 等级范围 | 含义 | 行动 |
|------|---------|------|------|
| **红色** | L1-L2 | 需要立即改进 | 生成改进路径 |
| **黄色** | L3 | 已标准化，可持续优化 | 列入优化建议 |
| **绿色** | L4-L5 | 优秀 | 维持和扩展 |

### 关键比率

- **红色维度占比**：红色维度数量 / 7。超过 50% 意味着组织急需系统性转型
- **最大落差**：最高维度等级 - 最低维度等级。落差 ≥3 级标志严重不平衡
- **流程层 vs 基础设施差距**：流程维度（D2-D7）平均等级 - 基础设施维度（D1）等级。D1 作为基础设施层跨越个人和组织，不纳入任一侧的平均计算

## 三种组织形状

雷达图的**形状**比任何单一维度的等级更有诊断价值。三种典型形状对应三种不同的转型策略。

### 均衡型

**特征：** 7 个维度的等级相对均匀，落差 ≤2 级。

**典型雷达图：** 接近正七边形，虽然可能整体偏小（全 L2）或偏大（全 L4），但各维度差异不大。

**诊断含义：** 组织在 AI 原生转型上走的是"齐步走"路线——各方面同步推进，没有明显短板。

**识别规则：**
- `max(levels) - min(levels) ≤ 2`
- 没有任何维度比其他维度高出 2 级以上

**转型策略：**
- **如果全局偏低（均值 ≤ L2）**：选择 1 个红色维度作为突破口，通过单点成功建立信心
- **如果全局中等（均值 L3）**：聚焦最容易提升到 L4 的维度，追求数据驱动的质变
- **如果全局偏高（均值 ≥ L4）**：转向 L5 的自适应能力建设，关注跨团队知识扩散

### 偏科型

**特征：** 部分维度显著高于其他维度，落差 ≥3 级。通常是"个人层高、组织层低"的模式。

**典型雷达图：** 一侧明显突出，另一侧凹陷。最常见的偏科模式：D1（AI 工具采纳度）L4 + D4（人类审查体系）L1——工具用得很猛，但审查体系没跟上。

**诊断含义：** 组织在某些方面已经很先进，但系统性短板制约了整体效能。就像一个学生数学 100 分但语文 30 分——不能用数学的优势弥补语文的缺失。

**识别规则：**
- `max(levels) - min(levels) ≥ 3`
- 不满足尖刺型规则（即高维度 ≥3 个，或低维度 <4 个）

**转型策略：先补短板**
- **优先补齐最低的红色维度**——短板限制了其他高维度的效能发挥
- **利用高维度作为信心基础**——"我们在 X 方面已经做得很好了，现在同样的方法论可以帮我们解决 Y"
- **避免继续拔高已经高的维度**——边际效益递减，且加剧不平衡

### 尖刺型

**特征：** 有 1-2 个极高的维度（L4-L5），其余大部分在 L1-L2，形成尖刺形状。

**典型雷达图：** 有突出的尖角，整体面积很小。典型场景：一个先行团队建立了完善的审计证据链（D6 治理与合规 L4），但其他维度完全没有跟上。

**诊断含义：** 组织中有"先行者"或"飞地"——在某个局部做得非常深入，但能力完全没有扩散。

**识别规则：**
- 存在至少 1 个维度 ≥ L4
- 且 ≥4 个维度 ≤ L2
- 高维度和低维度之间的断崖明显

**转型策略：先巩固优势，再扩展**
- **保护和展示尖刺**——这是组织变革的"灯塔"，用数据证明"这样做是有效的"
- **从尖刺向相邻维度扩散**——找到与高维度自然连接的下一个维度（如从 D6 治理→D4 审查体系）
- **避免同时全面铺开**——尖刺型组织的变革资源通常集中在少数人手中，分散会稀释效果

## 改进路径推荐逻辑

### 路径生成规则

改进路径仅从**红色维度（L1-L2）**生成。每条路径关联具体的 SAND Skill、预期时间和 ROI 范围。

**路径生成算法：**

1. **收集所有红色维度**（L1 或 L2）
2. **按优先级排序**：
   - 第一优先级：组织形状驱动（偏科型优先补最低，尖刺型优先补尖刺相邻）
   - 第二优先级：最快见效优先（有现成 Skill 可直接运行的维度排前面）
   - 第三优先级：依赖关系（某些维度是其他维度的前提——如 D2 意图驱动 是 D3 编排的前提）
3. **为每条路径匹配 Skill 和预期效果**

### 维度→Skill→ROI 映射表

| 红色维度 | 推荐 Skill | 典型路径 | 预期见效时间 | 预期 ROI |
|---------|-----------|---------|------------|---------|
| **D1 AI 工具采纳度 L1** | （外部动作：工具选型和部署） | 标准化团队 AI 工具配置 | 1-2 周 | 开发者 AI 使用率从散发到 >80% |
| **D2 意图驱动成熟度 L1** | `sand-create-intent` | 在 1-2 个项目中引入意图声明工作流 | 2-3 周 | 意图首通率从 0% 到 ≥40% |
| **D3 编排能力 L1** | `sand-design-orchestration` | 为 3 个典型场景设计编排方案 | 3-4 周 | 复杂任务完成时间减少 |
| **D4 人类审查体系 L1** | `sand-validate-delivery` | 引入三通道并行验证到 PR 流程 | 2 周 | PR 审查中位时间 -40%，变更失败率 -30% |
| **D5 学习与资产化 L1** | `sand-run-retrospective` | 启动 AI 资产化循环 | 6 周 | 资产复用率 0% → 20% |
| **D6 治理与合规 L1** | `sand-governance-audit` | 建立审计事件记录机制 | 4 周 | 可通过模拟审计检查 |
| **D7 组织文化 L1** | （组合多个 Skill） | 最小切口策略：单痛点→单 Skill→单团队 | 3-6 周 | ≥1 个团队主动请求扩展 |

### 路径模板

每条改进路径使用以下结构化模板：

```yaml
# 改进路径模板
pathway:
  id: "P-D4-L1-to-L2"
  target_dimension: "D4-人类审查体系"
  current_level: L1
  target_level: L2
  timeframe: "2 周"
  
  actions:
    - step: 1
      description: "在 PR 流程中引入 sand-validate-delivery 三通道检查"
      skill: "sand-validate-delivery"
      effort: "0.5 人日配置 + 团队 30 分钟培训"
    - step: 2
      description: "运行 2 周，收集验证数据"
      skill: null
      effort: "团队日常使用"
    - step: 3
      description: "基于 2 周数据评估效果"
      skill: "sand-assess-maturity (循环校准模式)"
      effort: "1 小时"
  
  expected_outcomes:
    - metric: "PR 审查中位时间"
      direction: "下降"
      range: "30%-50%"
    - metric: "变更失败率"
      direction: "下降"
      range: "20%-40%"
  
  prerequisites:
    - "团队使用 Git 和 PR 工作流"
    - "至少 1 个 AI 编码工具已部署"
  
  risks:
    - "团队可能将三通道验证视为'又多一个检查流程'——需要用首次运行的实际发现来化解抵触"
```

### 组织形状对路径优先级的影响

| 组织形状 | 路径排序策略 | 示例 |
|---------|------------|------|
| **均衡型** | 选择最快见效的红色维度 | 如果 D4 和 D5 都是 L1，先做 D4（2 周见效）再做 D5（6 周见效） |
| **偏科型** | 优先补最低维度（短板） | D1=L4 但 D4=L1，优先补 D4——否则高工具采纳度反而加速质量恶化 |
| **尖刺型** | 先巩固尖刺相邻维度 | D6=L4 其余 L1，先补 D4（审查与治理自然连接），再向 D2、D3 扩散 |

## 维度间依赖关系

某些维度的提升是其他维度的前提：

```
D1 (AI 工具采纳度) ≥ L2
    └── 前提条件 for D2, D3
        （没有标准化的 AI 工具，无法谈意图驱动或编排）

D2 (意图驱动成熟度) ≥ L2
    └── 前提条件 for D3
        （没有结构化意图，编排方案没有输入）

D4 (人类审查体系) ≥ L2
    └── 前提条件 for D6
        （没有审查记录，审计证据链无法建立）

D5 (学习与资产化) — 独立
    └── 可以在任何阶段启动，不依赖其他维度

D7 (组织文化) — 涌现性
    └── 通常由其他维度的成功推动，而非直接建设
```

改进路径推荐逻辑必须尊重这些依赖关系——不能推荐一个前提条件未满足的路径。

## YAML 化提取指南

本文档的结构设计直接支持向 `data/pathway-rules.yaml` 的操作化提取：

```yaml
# 示例：pathway-rules.yaml 的预期结构
organizational_shapes:
  balanced:
    rule: "max(levels) - min(levels) <= 2"
    strategy: "选择最快见效的红色维度"
  skewed:
    rule: "max(levels) - min(levels) >= 3 AND has_l4_and_l1"
    strategy: "先补短板"
  spiked:
    rule: "count(levels >= 4) <= 2 AND count(levels <= 2) >= 4"
    strategy: "先巩固优势再扩展"

dimension_skill_mapping:
  D1: { skill: null, note: "外部工具部署" }
  D2: { skill: "sand-create-intent", timeframe: "2-3 周" }
  D3: { skill: "sand-design-orchestration", timeframe: "3-4 周" }
  D4: { skill: "sand-validate-delivery", timeframe: "2 周" }
  D5: { skill: "sand-run-retrospective", timeframe: "6 周" }
  D6: { skill: "sand-governance-audit", timeframe: "4 周" }
  D7: { skill: null, note: "组合多个 Skill" }

dependencies:
  D2: { requires: "D1 >= L2" }
  D3: { requires: "D2 >= L2" }  # 传递依赖: D1 >= L2 通过 D2 隐含满足
  D6: { requires: "D4 >= L2" }
```
