# SDC 总览

## 什么是 SDC

SDC（SAND Development Cycle）是 SAND 框架的核心方法引擎，类比 TOGAF 的 ADM（Architecture Development Method）。它定义了 AI 原生开发的标准循环方法——7 个阶段围绕治理中心轴形成闭环，每一圈产生可复用的 AI 资产，使下一圈更高效。

## 7 阶段 + 治理中心轴

| 阶段 | 核心问题 | 核心产出 |
|------|---------|---------|
| **Assess** | 我们在哪里？准备好了吗？ | 成熟度评估报告、改进计划 |
| **Intent** | 解决什么问题？成功长什么样？ | 意图声明、执行契约 |
| **Orchestrate** | 谁来做？怎么协作？ | 编排方案、Agent拓扑图 |
| **Build** | AI生成，人类审查 | 综合交付包 |
| **Validate** | 达标了吗？安全吗？ | 验证报告、质量门禁决策 |
| **Operate** | 上线、监控、持续验证 | 运营仪表盘、生产验证报告 |
| **Learn** | 学到了什么？什么可资产化？ | AI资产、复盘报告 |
| **Governance** | 贯穿全程的治理 | 审计日志、合规报告 |

## 非均匀节奏

SDC 与传统方法循环的关键区别：各阶段的"转速"不同。这是 AI 原生开发特有的——AI 可能在几分钟内生成传统需要几天的代码量，但人类审查时间不会等比压缩。

| 阶段 | 典型时长 | 节奏特点 |
|------|---------|---------|
| Assess | 首次2-4周 / 循环校准1-2天 | 双模运行 |
| Intent | 数小时到数天 | 取决于意图复杂度 |
| Orchestrate | 数小时（成熟团队可复用配方，分钟级） | 配方复用加速 |
| Build | 脉冲式（AI 10-30min + 审查30-60min） | 速度悖论 |
| Validate | 三通道并行，数小时到1天 | 并行加速 |
| Operate | 持续运行 | 信号持续采集 |
| Learn | 每轮循环结束，1-2天 | 资产化而非行动项 |

## 阶段间回退路径

SDC 不是单向流转的，它有结构化的回退机制：

- **Validate → Build**（打回）：代码质量或安全问题，回到 Build 微调
- **Validate → Intent**（重定向）：架构偏离或意图偏差，回到 Intent 重新定义
- **Learn → Assess**（飞轮闭环）：学习成果和资产反馈到下一轮评估

每次回退都记录为"意图偏差事件"，用于 Learn 阶段分析改进。

## 四层嵌套的 SDC

SDC 在组织的四个层级上以不同粒度和节奏运转：

- **L1 个体层**：微型循环，FDE+ 与 AI 的单兵协作
- **L2 团队层**：标准循环，Pod 内部的完整 7 阶段
- **L3 产品层**：战略循环，跨 Pod 的投资假设驱动
- **L4 组织层**：治理循环，组织级 AI 战略和成熟度管理

L4 的意图分解为 L3 的投资假设，L3 分解为 L2 的组合意图，L2 分解为 L1 的原子意图。L1 的学习成果向上汇聚。

## 与传统方法的对比

| 维度 | TOGAF ADM | Scrum | SAFe PI | SDC |
|------|----------|-------|---------|-----|
| 循环驱动力 | 架构需求 | 时间盒（Sprint） | 时间盒（PI） | 意图流 |
| 阶段数 | 9 | 4事件循环 | PI级别事件 | 7+治理 |
| 节奏 | 均匀 | 固定（2周） | 固定（8-12周） | 非均匀 |
| 产出 | 架构文档 | 可工作软件增量 | PI目标 | 可工作软件 + AI资产 |
| 独特阶段 | — | — | — | Orchestrate |
