# D2：组织分层模型

[Framework DNA #61]：SAND 四层模型的完整定义

Phase 1 中提出了四层概念（Individual→Pod→Product→Organization），现在把每一层拆解到与 SDC 对齐——每一层都有自己运转的 SDC 循环，但粒度和节奏不同：

L1 个体层（Individual Level）

> 一个 FDE+ 与 AI 的单兵作战

| 维度 | 定义 |
|---|---|
| 核心单元 | 1个 FDE+ + N个 AI Agent |
| SDC 运转方式 | 微型循环——Intent（分钟级）→ Orchestrate（选择Agent，秒级）→ Build（AI生成，分钟级）→ Validate（自动化检查，秒级）。Assess/Learn 被吸收到日常习惯中 |
| 管理的意图粒度 | 单个原子意图（一个函数、一个组件、一个Bug修复） |
| 关键角色 | FDE+（兼任所有职责） |
| 关键仪式 | 无正式仪式——个人节奏的脉冲式工作 |
| 关键度量 | 个人 AI 杠杆率、个人意图首通率 |
| 工具焦点 | IDE集成AI（Cursor/Claude Code/Copilot）、个人上下文管理 |

L2 团队层（Pod Level）

> Mission Pod 内部的协同作战

| 维度 | 定义 |
|---|---|
| 核心单元 | 3-7个 FDE+ + AI编排师 + 问题域负责人（可兼任） |
| SDC 运转方式 | 标准循环——完整7阶段，Intent由问题域负责人驱动，Orchestrate由AI编排师设计 |
| 管理的意图粒度 | 组合意图（一个Feature、一个用户流程、一个模块） |
| 关键角色 | FDE+（执行）、AI编排师（设计协作方案）、问题域负责人（定义意图） |
| 关键仪式 | 每日意图审查（30min）、每周假设会议 |
| 关键度量 | Pod 意图吞吐量、Pod AI 杠杆率、审查瓶颈率 |
| 工具焦点 | Agent编排平台、团队上下文共享、意图队列管理 |

[Framework DNA #62]：Pod 的组建原则
Concept：Pod 不是固定团队，而是围绕问题域动态组建的——
  - 组建触发：一个投资假设被批准时，组建 Pod 来执行
  - 解散触发：投资假设被验证（证实或证伪）后，Pod 可解散，成员流入其他 Pod
  - 能力组合原则：每个 Pod 必须覆盖5种原子能力（领域架构力/AI协作力/系统交付力/质量保障力/数据感知力），但不一定需要5个人——一个人可以覆盖多种能力

L3 产品层（Product/Domain Level）

> 跨 Pod 的产品域治理

| 维度 | 定义 |
|---|---|
| 核心单元 | 多个 Pod + 产品域负责人 |
| SDC 运转方式 | 战略循环——Assess（季度）、Intent（投资假设级）、Orchestrate（跨Pod资源编排）。Build/Validate/Operate 下放给各 Pod |
| 管理的意图粒度 | 投资假设（一个产品方向、一个市场机会） |
| 关键角色 | 产品域负责人（投资决策）、多个Pod的AI编排师（协调） |
| 关键仪式 | 月度投资假设评审、季度成熟度评估 |
| 关键度量 | 投资假设验证速率、跨Pod资产复用率、产品域意图吞吐量 |
| 工具焦点 | 投资组合管理、AI资产库、跨Pod上下文同步 |

L4 组织层（Organization Level）

> 企业级 AI 原生治理

| 维度 | 定义 |
|---|---|
| 核心单元 | 整个组织 + AI 转型领导层 |
| SDC 运转方式 | 治理循环——Assess（半年/年度全面诊断）、Intent（组织级AI战略目标）。其他阶段通过政策和标准影响下层 |
| 管理的意图粒度 | 组织战略（AI转型目标、文化变革、能力建设路线） |
| 关键角色 | AI转型负责人（CTO/CAIO）、变革催化师团队 |
| 关键仪式 | 半年度AI成熟度诊断、年度AI战略评审 |
| 关键度量 | 组织成熟度（L1-L5）、组织级AI杠杆率、AI资本化ROI |
| 工具焦点 | 成熟度评估平台、AI使用章程管理、组织级度量仪表盘 |

[Framework DNA #63]：四层嵌套的 SDC 循环
Concept：四层不是独立运转的，而是嵌套的——
  - L4 的 Intent（组织战略）分解为 L3 的多个投资假设
  - L3 的投资假设分解为 L2 Pod 的多个组合意图
  - L2 的组合意图分解为 L1 个体的多个原子意图
  - L1 的学习成果向上汇聚到 L2/L3/L4 的 Learn 阶段

类比 SAFe：SAFe 有 Team/Program/Large Solution/Portfolio 四层，每层有不同的迭代节奏（Sprint/PI/Solution Train/Annual）。SAND 也是四层不同节奏，但驱动力不是时间盒（Sprint），而是意图流。
