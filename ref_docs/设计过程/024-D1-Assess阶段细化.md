# D1：评估（Assess）阶段细化

## 为什么 Assess 是循环的"校准仪"

### [Framework DNA #41]：Assess 的双模运行深化

Concept：前面提到 Assess 有两种模式。现在把它们完整定义——

**模式一：首次诊断模式（Initial Diagnosis）**
- 触发条件：组织首次采纳 SAND，或一个全新的团队/产品域开始转型
- 持续时间：2-4 周
- 目标：建立基线（Baseline），知道"我们从哪里出发"

**模式二：循环校准模式（Cycle Calibration）**
- 触发条件：上一轮 SDC 的 Learn 阶段完成
- 持续时间：1-2 天
- 目标：吸收上一轮学习成果，校准下一轮方向

两种模式共用同一套评估框架，但深度和广度不同——首次诊断做全面扫描，循环校准做重点检查。

## A1：成熟度评估框架（Maturity Assessment Framework）

### [Framework DNA #42]：SAND 成熟度模型的操作化

Concept：v1 中定义了 L1-L5 成熟度模型，但缺少"怎么评"。现在为每个级别定义可度量的评估维度——

```yaml
maturity_assessment:
  dimensions:
    - id: DIM-01
      name: "AI 工具采纳度"
      l1: "个别开发者自发使用，无统一标准"
      l2: "团队级统一工具平台，有使用规范"
      l3: "全组织标准化，AI 嵌入 SDLC 全流程"
      l4: "AI 使用数据驱动优化，持续调优工具链"
      l5: "工具自适应演进，新模型能力自动评估和集成"
      evidence_type: "工具使用日志、平台覆盖率报告"

    - id: DIM-02
      name: "意图驱动成熟度"
      l1: "需求以传统 User Story 形式存在"
      l2: "开始尝试结构化意图声明"
      l3: "意图声明标准化，CLEAR 检查通过率 >70%"
      l4: "意图模式库形成，复用率 >40%"
      l5: "AI 辅助意图生成和优化，首通率 >80%"
      evidence_type: "意图声明审计、CLEAR 评分数据"

    - id: DIM-03
      name: "编排能力"
      l1: "无编排概念，每次临时决定用什么 AI 工具"
      l2: "有基本的 Agent 选型标准"
      l3: "标准拓扑模式投入使用，编排配方库初建"
      l4: "编排方案数据驱动优化，AI 杠杆率可度量"
      l5: "AI 参与编排推荐，自适应拓扑选择"
      evidence_type: "编排方案记录、杠杆率仪表盘"

    - id: DIM-04
      name: "人类审查体系"
      l1: "AI 输出无系统性审查，质量靠个人自觉"
      l2: "有审查清单，关键产出必须人类审查"
      l3: "三级介入模型（HIP-1/2/3）运行，覆盖率可度量"
      l4: "介入级别动态调整机制运行，审查效率持续优化"
      l5: "信任校准机制成熟，审查资源精准配置"
      evidence_type: "审查覆盖率报告、HIP 分布数据"

    - id: DIM-05
      name: "学习与资产化"
      l1: "无系统性经验沉淀"
      l2: "有定期复盘会议，产出行动项"
      l3: "AI 复盘标准议程运行，5类资产分类入库"
      l4: "飞轮加速指标持续改善，资产复用率 >40%"
      l5: "资产生态自运转，知识自动发现和更新"
      evidence_type: "资产库统计、飞轮指标趋势"

    - id: DIM-06
      name: "治理与合规"
      l1: "无 AI 使用治理"
      l2: "AI 使用章程发布，基本合规边界定义"
      l3: "审计链完整，所有 AI 参与决策可追溯"
      l4: "治理数据驱动，违规自动检测和预警"
      l5: "自适应治理，规则随 AI 能力和风险动态调整"
      evidence_type: "审计日志、合规检查报告"

    - id: DIM-07
      name: "组织文化"
      l1: "AI 被视为可选工具，使用是个人选择"
      l2: "组织鼓励 AI 使用，有培训计划"
      l3: "AI 协作成为默认工作方式"
      l4: "容差文化成熟，团队适应非确定性输出"
      l5: "AI 原生文化完全内化，持续追踪前沿并自我演进"
      evidence_type: "文化调查、培训参与率、AI 使用频率"
```

Novelty：7个维度覆盖了 SAND 的全部核心关切——工具、意图、编排、审查、学习、治理、文化。每个维度都有 L1-L5 的具体描述和证据类型，使评估从"主观感觉"变成"结构化诊断"

## A2：差距分析与转型路线（Gap Analysis & Transformation Path）

### [Framework DNA #43]：雷达图诊断 + 转型路径生成

Concept：7个维度的评估结果形成雷达图，立即可视化组织的"形状"——

- **均衡型**（各维度差距不大）→ 建议全面提升到下一级
- **偏科型**（某些维度高某些维度低）→ 优先补短板，短板是系统瓶颈
- **尖刺型**（个别维度特别高）→ 利用强项带动弱项（如编排能力强但意图质量差 → 用编排能力倒逼意图标准化）

每种形状对应不同的转型策略。SAND 应预定义这些转型策略模板，让组织不需要从零设计转型路线。

Novelty：传统成熟度模型只告诉你"你在哪一级"，SAND 的 Assess 还告诉你"从你当前的形状出发，最佳路径是什么"

## A3：Assess 的可执行工具

### [Framework DNA #44]：Assess 阶段的"方法论即代码"实现

Concept：Assess 应该提供一套可执行的评估工具包——

| 工具 | 形态 | 功能 |
|------|------|------|
| 成熟度自评问卷 | 交互式检查清单（可集成为 Agent 工作流） | 引导式问答，自动计算各维度得分 |
| 数据采集脚本 | 自动化脚本（接入 Git/CI/项目管理工具） | 自动采集度量指标——提交频率、AI 工具调用量、审查覆盖率等 |
| 雷达图生成器 | 可视化工具 | 基于评估结果自动生成组织成熟度雷达图 |
| 转型路径推荐器 | 决策引擎（规则+AI辅助） | 基于雷达图形状推荐转型策略和优先行动项 |
| 基线快照 | 结构化报告模板 | 记录当前评估结果作为基线，供后续循环对比 |

Novelty：这些工具不是"独立的评估软件"，而是 SAND 框架自带的、可执行的评估能力——你安装 SAND 就获得了评估自己的能力
