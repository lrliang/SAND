# 想法萌芽

/bmad-brainstorming 我准备创建一个方法论： 规模化AI驱动开发方法 ；目标是帮助软件开发组织成为AI Native的组织，里面的每个人都能正确高效不浪费地使用AI
包含理论基础（要引用行业大能比如Martin Fowler等人的论文）、工具、实施路径、评价（准则、方式、工具）
要逻辑完备，类似Lean、 Togaf、SAFE（Scaled Agile Framework）、Design Thinking等等  我和LLM对话得到了这样两个版本见docs；
我觉得概念设计很好，但是我需要非常完整完善的体系；类似SAFE、Scrum、Togaf这样的体系性框架；我需要框架的理论说明、支撑理论的工具、人的关系、人和模型的关系、人和工具的关系、人和软件项目的关系等等诸如此类，在docs中应该要构建出树形结构的文档库

可以参考bmad-method的设计

这是一个极其精彩的发现！bmad-method 本身就是一个"AI原生框架"的活体样本。让我把分析结果和你的直觉结合起来，这里面有重大的洞见。

---

## Framework DNA #1：Scrum 式极简骨架 + AI原生新形态

Concept：SAND 应该像 Scrum Guide 一样有一个极简核心（可能10-20页），定义最少必要的元素，然后允许社区和组织自由扩展实践层
Novelty：不是做一个 SAFe 式的"全景大图"，而是做一个"种子框架"——核心小到可以一次读完，但具有生长性


## Framework DNA #2：bmad-method 的元模式启示

Concept：bmad-method 揭示了一个关键的结构范式——它不是一份"方法论文档"，而是一个可执行的方法论操作系统。它有4大模块（core/bmm/cis/tea）、13个Agent角色、63个技能、4层配置系统、阶段式工作流。它自身就是"方法论即代码"（Methodology-as-Code）
Novelty：传统框架（SAFe/TOGAF/Scrum）是"人读的文档"，bmad-method 是"AI执行的工作流"——SAND 可能需要同时是两者

---

这引出了一个我觉得非常深刻的洞见：

SAND 作为"AI原生方法论"，它自身就应该是 AI 原生的。 也就是说：

- Scrum 是一份人类读的指南 → 人类来执行
- TOGAF 是一套架构方法 → 人类来遵循
- bmad-method 是一套 AI 执行的工作流 → AI Agent 来运行，人类来引导
- SAND 应该是什么？→ 既是人读的方法论框架，又是 AI 可执行的实施工具

从 bmad-method 的架构中，我提取出几个特别值得 SAND 借鉴的结构要素：

| bmad-method 结构 | SAND 可借鉴的点 |
|---|---|
| 4大模块 (core/bmm/cis/tea) | SAND 也需要模块化——核心理论模块 + 实施模块 + 评价模块 + 工具模块 |
| Agent = 角色 + 人格 + 能力 | SAND 中 FDE+、AI编排师等角色不只是名称，应该有像 bmad 的 Agent 那样的"能力定义 + 行为规范" |
| 阶段式工作流 (analysis → planning → solutioning → implementation) | SAND 的四阶段转型路径也可以有类似的阶段门控和依赖关系 |
| Step-file 架构（严格顺序执行） | SAND 的实施指南可以做成 step-by-step 的确定性流程 |
| 4层配置系统（基础→用户→团队→个人） | SAND 的"AI使用章程"也可以分层——组织级→部门级→团队级→个人级 |
| Skill Manifest（63个技能的注册表） | SAND 也需要一个"能力/实践注册表"——列出所有可用的工具、模板、检查清单 |
