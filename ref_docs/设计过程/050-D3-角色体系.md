# D3：角色体系

[Framework DNA #64]：SAND 的四核心角色完整定义

|  | FDE+（全栈交付工程师） | AI 编排师 | 问题域负责人 | 变革催化师 |
|---|---|---|---|---|
| 核心使命 | 端到端交付问题解决方案 | 设计最优人-AI协作架构 | 定义正确的问题和成功标准 | 推动组织AI原生能力成长 |
| 主要原子能力 | 全部5种（综合体） | AI协作力+系统交付力 | 领域架构力+业务洞察 | AI协作力+组织发展 |
| SDC 主导阶段 | Build, Validate | Orchestrate | Intent, Assess | Learn |
| SDC 参与阶段 | 全部 | Build(审查编排效果), Learn | Validate(验收), Operate(业务验证) | Assess(组织评估), 全部(观察记录) |
| 活跃层级 | L1, L2 | L2, L3 | L2, L3 | L3, L4 |
| 关键决策权 | 代码审查通过/打回、技术实现方案 | Agent拓扑选择、人类介入点设置 | 意图优先级、投资假设审批 | 资产化决策、培训方向 |
| 成长路径 | 初级FDE+ → 高级FDE+ → AI编排师 或 问题域负责人 | 高级FDE+/架构师 → AI编排师 → 产品域级编排顾问 | 产品经理/技术主管 → 问题域负责人 | 资深工程师 → 变革催化师 → AI转型负责人 |

[Framework DNA #65]：角色不是职位，是责任域
Concept：关键原则重申——一个人可以同时承担多个角色（特别是在小团队中，FDE+ 可能同时承担编排师职责）。角色随问题域流动而不随组织架构固定。但有一条不可违反的约束：
  - 意图定义者和意图验证者不能是同一个人——这防止了"自说自话"
  - 问题域负责人定义 Intent → FDE+ 执行 Build → 不同的 FDE+ 或问题域负责人做 Validate

Novelty：这类似于财务审计中"不相容职务分离"的原则，应用到了人-AI协作场景
